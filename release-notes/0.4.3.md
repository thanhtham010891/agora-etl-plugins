# agora-etl-plugins 0.4.3

`0.4.3` is the coordinated official-plugin release for `agora-etl 0.4.6`.

## Upgrade requirement

Install it with the matching core release:

```bash
pip install --upgrade "agora-etl>=0.4.6,<1" "agora-etl-plugins>=0.4.3,<1"
```

The new floor is intentional. Official sources and sinks use the public
`SourceIdentity` and delivery-policy contracts added in `agora-etl 0.4.6`.
Installing this plugin release with the previously published core `0.4.5`
would fail during entry-point import, so metadata now rejects that unsafe
combination before deployment.

## Delivery-policy safety

Generic PostgreSQL upserts and Redis `SET` writes no longer infer replay safety
from arbitrary application callbacks. They require an explicit
`replay_safe_key_contract=True` assertion after the operator establishes a
stable delivery key/conflict key invariant. The dedicated Kafka → PostgreSQL
profile keeps its separate delivery-key acceptance gate.

The assertion is rejected for incompatible modes: PostgreSQL needs `upsert=True`
and Redis needs `mode="set"`.

## Redis Streams → PostgreSQL profile

The certified Redis Streams → PostgreSQL profile derives a stable
`stream:message_id` delivery key, upserts through PostgreSQL before issuing
`XACK`, and reports fail-closed acceptance findings for unsafe acknowledgement,
conflict-key, write-safety, replay-capability, or readiness configuration.
It is at-least-once: a crash after PostgreSQL commits but before `XACK` can
replay a message, and the delivery key makes that replay idempotent at the
target row.

## Operational note

Live BigQuery release validation remains opt-in: it requires an explicitly
authorized project, dataset, and credentials. The local Kafka, PostgreSQL,
Redis, and MinIO/S3 release gates remain reproducible through the declarative
test matrix.

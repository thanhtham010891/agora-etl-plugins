# agora-etl-plugins 0.4.2

`0.4.2` is a release-hardening and compatibility-focused update for the
official first-party plugin bundle. It aligns the package with the current
`agora-etl 0.4.5` core line while tightening operational guardrails, mixed-core
development behavior, and release verification.

## Highlights

- Raised the supported core floor to `agora-etl>=0.4.5,<1` so the plugin
  bundle ships against the current `doctor`, observability, and supportability
  contract line.
- Added a defensive `DLQPayloadPolicy` shim in `agora_plugins.dlq_policy` so
  DLQ redaction and encryption behavior remains available during mixed-version
  local workflows and wheel smoke checks.
- Added Kafka poison-policy compatibility handling for environments that have
  not yet picked up the newest core failure exports.
- Added Kafka plaintext posture warnings when `PLAINTEXT` is pointed at
  obviously non-local brokers or non-dev environments.
- Filtered noisy redis-py cluster driver deprecation warnings in the async
  Redis cluster connection path until upstream exposes a stable constructor
  path.
- Strengthened release automation with base-gate diagnostics upload, a reusable
  Postgres release-gate wrapper, a lane-selectable nightly periodic matrix, and
  release preflight jobs that run before build/publish.

## Upgrade Notes

- Upgrade `agora-etl` to `0.4.5` before installing `agora-etl-plugins 0.4.2`.
- **BigQuery source checkpoints:** `checkpoint_column=...` now requires an
  explicit safety declaration. Set `checkpoint_column_is_unique=True` only
  when the column is genuinely unique, or configure
  `checkpoint_tiebreaker_column=...` and order by both columns. A saved scalar
  checkpoint cannot resume under the new composite-cursor configuration; start
  a new run or migrate it to `{"cursor": ..., "tiebreaker_cursor": ...}`.
- **S3 sink object layout:** output keys now include `run_id=<run-id>`, for
  example `exports/run_id=<run-id>/dt=2026-07-20/part-00000.parquet`.
  Downstream discovery rules must include this path component. Reusing a run ID
  now fails closed on an existing object instead of overwriting it.
- **Kafka transactions and retry:** `transactional_id` only configures a
  transaction-capable producer. Set `transaction_per_batch=True` to wrap
  `write_batch()` calls, or use `async with sink.transaction()` explicitly.
  The sink now applies its retry policy to both send submission and delivery
  acknowledgement; retry policies should only include errors safe to retry.
- **Distributed fencing:** fencing-token counters no longer expire by default.
  An explicitly configured `fencing_key_ttl_seconds` remains supported but
  weakens monotonicity after expiry. Redis persistence and downstream rejection
  of lower tokens remain required for a strong stale-writer barrier.
- Teams intentionally using Kafka `PLAINTEXT` outside local/dev topologies
  should expect a warning and should either switch to TLS/SASL or treat the
  warning as an explicit risk acknowledgement.

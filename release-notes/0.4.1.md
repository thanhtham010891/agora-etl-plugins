# agora-etl-plugins 0.4.1

`0.4.1` is a patch hardening release on the existing `0.4.x` plugin line.
It keeps the current runtime compatibility floor of `agora-etl>=0.4.1,<1`
while tightening failure handling, atomicity, and operational defaults across
Redis, PostgreSQL, Kafka, distributed coordination, and Anthropic support.

## Highlights

- Redis stream poison handling now acknowledges reclaimed deserialize failures
  once they have been handled, which closes the reclaim-loop window for
  `LOG_AND_CONTINUE` and DLQ-backed recovery paths.
- Redis DLQ storage now updates primary and secondary indexes atomically,
  including Redis Cluster-safe key tagging and fallback reads for legacy index
  layouts.
- Redlock fencing now issues one authoritative fencing token from the primary
  Redis connection and validates that same token across quorum-node lease
  acquire, renew, release, and validation paths.
- PostgreSQL sink flushes are now atomic across SQL, COPY, and COPY-merge
  write strategies, including `ALIGN_TO_TARGET` schema alignment flows.
- PostgreSQL source replica-staleness guards now block stale active standbys
  mid-stream and reject non-primary fallback connections when
  `on_replica_stale="route_primary"` is requested.
- Kafka poison-record progress now matches policy intent:
  `DLQ_AND_CONTINUE` preserves forward progress, while
  `DLQ_AND_FAIL_CLOSED` still stops the source on unresolved DLQ failure.
- Kafka Schema Registry deserializers now use bounded caches, and serializers
  default to registering only missing subjects instead of always creating new
  versions.
- The Anthropic provider now validates supported production model ids by
  default, hardens structured-output parsing, truncated-response handling, and
  retry-after aware retries, and now defaults to active Claude model ids
  instead of retired 3.x snapshots.

## Upgrade Notes

- No compatibility change is introduced on the `0.4.x` line.
- No config migration is required for existing Redis, Kafka, or PostgreSQL
  pipelines.
- Teams that relied on unconditional Schema Registry auto-registration for
  existing subjects should set `auto_register="always"` explicitly.
- Teams using unlisted Anthropic model ids must now opt in with
  `allow_unknown_models=True`.
- Teams still pinned to retired Anthropic Claude 3.x-era snapshots should
  migrate to currently active replacements before upgrading.
